# 账单分析 Skill

分析支付宝或微信导出的账单文件（xlsx/csv）。用户只需将账单文件放入 `input/` 目录，运行解析脚本，即可获得标准化的合并数据和多维分析报告。

## 支持的文件格式

- 支付宝：csv（gbk/utf-8 编码）
- 微信：xlsx

## 处理流程

### Step 1: 批量解析

引导用户将用户将账单文件放入 `input/` 目录后，用户确认放入后执行：

```bash
python3 .claude/skills/bill-analyzer/scripts/parse_bill.py input/ -o cleaned_data.json
```

脚本自动完成：
- 扫描目录下所有 `.csv` 和 `.xlsx` 文件
- 自动检测表头行（微信第18行、支付宝第24行等位置不固定）
- 自动识别来源（支付宝/微信）
- 过滤无效交易：
  - 支付宝"不计收支"（余额宝收益等）
  - 微信中性交易（零钱充值等）
  - 交易失败/关闭/退款（未成功交易）
- 合并去重（相同订单号只保留一条）
- 字段标准化为统一结构
- 应用三个映射文件进行标准化

### Step 2: 确认数据与映射积累

解析完成后，向用户展示：
- 解析统计：有效记录数、过滤记录数
- 新发现的商户列表（不在 `merchant_clean_mapping.json` 中的）
- 新发现的分类映射（不在 `category_mapping.json` 中的）
- 支付方式标准化结果

**映射积累机制**：脚本解析时自动应用现有映射。对于不在映射表中的商户/分类：
1. 商户名：用启发式规则清洗（去门店号/去括号后缀/去微信前缀/去手机号），并自动追加到 `merchant_clean_mapping.json`
2. 分类：支付宝账单直接使用其自带的"交易分类"字段；微信账单根据"交易类型"推测分类，并自动追加到 `category_mapping.json`
3. 支付方式：用规则标准化（支付宝体系→"支付宝账户"，微信体系→"微信账户"，银行卡统一简称），并自动追加到 `payment_method_mapping.json`

**重要**：每次解析后映射文件都会自动增长。如果脚本的自动映射不准确，用户可以手动编辑映射文件（`scripts/` 目录下的 JSON 文件），下次运行即可生效。

### Step 3: 多维分析

```bash
python3 .claude/skills/bill-analyzer/scripts/analyze_bill.py cleaned_data.json
```

输出内容包括：
- **总览**：总收入、总支出、结余、月均支出
- **来源构成**：支付宝 vs 微信的收支对比
- **月度趋势**：按月汇总的收支数据
- **年度趋势**：按年汇总（跨年数据时显示）
- **分类占比**：支出分类饼图数据（Top 8 + 其他）
- **TOP商户**：按消费金额排序的 Top 10 商户
- **支付方式分布**：各支付渠道的使用比例
- **星期消费习惯**：一周消费分布
- **收入来源**：收入 Top 10

### Step 4: 交互式查询

支持用户进一步查询：
- 筛选特定时间段
- 筛选特定分类或商户
- 对比不同月份/年份
- 导出分析结果

## 映射文件说明

```
scripts/
├── merchant_clean_mapping.json   # 原始商户名 → 标准化商户名（自动积累）
├── category_mapping.json         # 标准化商户名 → 分类（自动积累）
└── payment_method_mapping.json   # 原始支付方式 → 标准化支付方式（自动积累）
```

所有映射文件均为可读的 JSON 格式，用户可手动编辑修正。

## 故障排查

如果解析出错：
- 检查表头是否被正确定位（查看 stderr 输出中的"表头行"信息）
- 检查 openpyxl 是否已安装：`pip3 install openpyxl`
- 支付宝 csv 如为 gbk 编码乱码，脚本会自动尝试多种编码
- 如果商户名大量未匹配，检查 `merchant_clean_mapping.json` 是否需要补充
